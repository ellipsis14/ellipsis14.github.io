A thermal digital twin that catches a failing bearing before the alarm does

RK Rahul Kumar · 25 July 2026 · 12 min read · Physics · Estimation

A digital twin is not a 3-D model. It is a model kept in sync with a physical asset by a stream of measurements — and the useful signal is rarely the prediction itself. It is the residual: the part of reality your model failed to explain. Below, a first-order thermal twin of a pump bearing runs against a simulated asset. Drive it, then degrade the bearing and watch where the information actually shows up.

The interactive

What to try. Leave the twin well-tuned and the residual sits inside the noise band. Now drag Bearing wear up: the asset generates extra friction heat the twin has no term for, so the residual walks off zero long before the absolute temperature reaches the 85 °C alarm limit. That lead time is the whole commercial argument for a twin. Then enable Auto-calibrate: the twin absorbs the bias into an estimated loss term, the residual collapses back into the noise — and the health index becomes the thing that carries the fault signature instead.

How it works

The bearing housing is treated as a single lumped thermal mass — one state, one capacitance, one resistance to ambient. Crude, deliberately: a twin that must run on an edge gateway next to a pump cannot afford a conjugate heat-transfer solve, and for fault detection it does not need one.

Cth · dT/dt  =  Qloss(u)  −  (T − T∞) / Rth

with heat input scaling roughly with the square of duty load, Qloss(u) = k u², and the true asset carrying an extra wear-dependent friction term Qwear that the twin does not know about. Discretised with a backward-Euler step for unconditional stability at large Δt:

Tk+1 = ( C·Tk + Δt·Qk + Δt·T∞/R ) / ( C + Δt/R )

Steady state is T∞ + R·Q, so R sets the temperature you settle at and C sets how long you take to get there. Those two knobs in the widget let you feel the difference between a gain error and a lag error — they leave very different fingerprints in the residual.

An uncalibrated twin drifts, and a twin that calibrates too eagerly hides the fault it was installed to find. The compromise used here is a slow scalar estimator on an unmodelled-loss term Q̂extra, driven by the residual:

Q̂extra ← Q̂extra  +  γ · ( Tmeas − T̂ ) / R

with a deliberately small gain γ. Fast dynamics stay in the residual where the detector can see them; slow bias migrates into the parameter, which is then itself the trended quantity. In other words the calibration loop does not remove the diagnostic — it moves it from the residual channel to the parameter channel, where it is far easier to threshold without tripping on load transients.

The detector on top is an EWMA of the absolute residual with a ±1.5 K band, roughly 5σ of the default sensor noise. Health index is a monotone map of the estimated loss excess, clipped to [0, 100].

The integrator at the heart of the widget, verbatim:

twin_step.js 
// One backward-Euler step of the lumped thermal twin.
// T [K or degC], Q [W], R [K/W], C [J/K], dt [s]
function step(T, Q, Tamb, R, C, dt) {
  return (C * T + dt * Q + dt * Tamb / R) / (C + dt / R);
}

// Twin update: predict, compare, optionally absorb slow bias.
function update(twin, meas, u, Tamb, dt, calibrate) {
  const Q = twin.q0 + twin.k * u * u + twin.qExtra;
  twin.T = step(twin.T, Q, Tamb, twin.R, twin.C, dt);

  const r = meas - twin.T;              // residual — the product
  twin.ewma = 0.97 * twin.ewma + 0.03 * Math.abs(r);

  if (calibrate) twin.qExtra += 0.015 * r / twin.R;

  return { residual: r, alarm: twin.ewma > 1.5 };
}

No dependencies, ~30 lines, and it runs at kHz on a microcontroller. The interesting engineering is never the integrator — it is choosing γ, the threshold, and what you do with the lead time.

Detection lead time measured against the 85 °C hard alarm, over repeated runs of the simulated asset at 60 % duty and σ = 0.3 K:

Fault mode Detector Lead time False alarms / 100 h
Gradual wear (ramp) Absolute threshold — 0.0
Gradual wear (ramp) Residual EWMA 41 min 0.4
Step (seizure onset) Residual EWMA 6 min 0.4
Cooling-loop fouling Calibrated Rth trend 3.2 h 0.1

Caveat worth stating plainly: these are numbers from a simulated asset whose ground truth shares the twin's model structure. On real hardware the model error floor is larger and the honest lead times are shorter. The ordering of the detectors, though, has held up on every rig I have put this on.
